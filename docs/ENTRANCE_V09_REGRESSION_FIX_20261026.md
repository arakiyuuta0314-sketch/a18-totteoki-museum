## 実際に確認した原因
- v09の基準画像を導入した際、新旧の展示枠座標が異なるのに、v3保存中の従来のfixture矩形を起動時に揃えていなかった。
- 水色の選択予定枠は新しい写真窓ではなく保存済みfixtureの矩形から描画していた。
- 旧P3/P5の全室画像を起動時に大量取得していた。P3は約39画像、P5は36画像。入口表示では不要。
- 新しい左右通路は床の奥下に位置するが、前景パーティションの当たり判定と入口の移動トリガーが噛み合わず、実際の到達が分かりにくかった。

## 修正
1. 以前のv3保存を読み込み、新しい固定展示枠3件の座標・寸法・設置種別だけを既定値へ揃え、CASによって1回だけ保存。作品ID/Blob/タイトル/メモ/進行を変更しない。既に一致していれば再保存しない。
2. 入口の写真のクリック範囲・掲示予告の緑枠を新しい写真窓の実寸と右手前の四辺形に合わせ、物理的な床の障害物矩形とは分離。
3. 左右の通行可能な床部分と判定範囲を整合。解放前後を示す小さい行先表示を入口の下側へ追加。Lv2左、Lv3右を変えない。
4. P3/P5のマニフェストは起動時検証するが、展示室の画像はその部屋に入る直前か保存済み展示室から復帰するときだけ取得。読み込み失敗はエラー、他室へ遷移してから描画不能になることを避ける。レベル上昇直後の装飾差分も取得する。
5. 修正したJSに個別のキャッシュ識別子を付与。IndexedDBスキーマはv3のまま。
